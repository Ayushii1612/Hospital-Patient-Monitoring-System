# Hospital-Patient-Monitoring-System
The **Hospital Patient Monitoring System** is a console-based C++ application designed to help healthcare professionals efficiently manage patients and monitor their vital signs in real time. It automates record keeping, tracks key health parameters, and instantly alerts doctors when a patient’s condition becomes critical. The system monitors five vital signs—**heart rate, blood pressure, oxygen level, temperature,** and **respiratory rate**—and automatically classifies patients into four priority levels: **CRITICAL, HIGH, MEDIUM,** and **LOW**. Using a **priority queue**, it ensures that critical alerts are processed first, preventing emergencies from being overlooked. Built with **modern C++ and STL**, it uses **maps** for fast patient lookups, **priority queues** for alert management, **vectors** for storing patient history, and **smart pointers** for safe memory handling. The system includes four main modules: **Patient Management** for handling patient details, **Vital Signs Monitoring** for recording and analyzing data, **Alert Management** for generating and prioritizing alerts, and **Reports & Analytics** for reviewing hospital performance. Overall, this project reduces manual work, minimizes human error, and ensures timely medical response through intelligent and automated monitoring.

✨ Features:
1. Patient Management -> The system automatically generates unique patient IDs starting from 1001 to avoid duplication and conflict. It stores complete patient profiles including name, age, gender, diagnosis, ward assignment, and admission date. Multiple ward types are supported such as Emergency, ICU, General, Private, and Pediatrics. Users can quickly search patients by their ID, track active or discharged status, and discharge patients safely with timestamps while preserving all records for future reference.
2. Vital Signs Monitoring -> This module continuously monitors five vital signs — heart rate, blood pressure, oxygen saturation, temperature, and respiratory rate. It performs real-time risk assessment and categorizes each reading into CRITICAL, HIGH, MEDIUM, or LOW priority. All five vitals can be entered in bulk for efficiency, and every reading is stored with a timestamp to build a complete patient history. The system relies on medically validated threshold ranges based on clinical standards to ensure accuracy.
3. Alert Management System -> Alerts are automatically generated whenever a patient’s vitals exceed normal ranges. A priority-based queue ensures CRITICAL alerts are handled first, with same-level alerts processed in FIFO order. Each alert includes detailed information such as patient ID, affected vital, abnormal value, and timestamp. Recommended actions are displayed based on the priority level, guiding healthcare staff to respond appropriately. The system also keeps a full history of all processed alerts and allows users to view pending alerts without clearing them.
4. Reports & Analytics -> The reporting module provides a real-time dashboard displaying hospital statistics, including total, active, and discharged patients. It visualizes the distribution of patient risk levels and maintains records of generated, pending, and processed alerts. Users can generate critical patient reports, view ward-wise summaries, and export all reports to text files with timestamps. This feature also supports basic statistical analysis to help in data-driven hospital management and decision-making.
5. System Features -> The system includes robust input validation to ensure all data entries fall within valid ranges and provides clear error messages for incorrect inputs. It handles all types of runtime errors gracefully, preventing crashes or data loss. Memory is efficiently managed using smart pointers (shared_ptr) to avoid leaks. All session data remains stored in memory while the program runs, ensuring smooth operation. With a clean, menu-driven interface featuring 17 organized options, the application is user-friendly and easy to navigate. It is also cross-platform, running seamlessly on Windows, Linux, and macOS.

💻 Technology Stack:
1. Programming Language: C++ (C++11 or higher)
2. Standard Library: C++ STL (Standard Template Library)
3. Data Structures: map<int, shared_ptr<Patient>> for patient database, priority_queue<Alert> for alert management with custom comparator, vector<VitalReading> for vital signs history, and vector<Alert> for processed alerts log
4. Memory Management: Smart pointers (shared_ptr)
5. Compiler Support: g++ (GCC), MSVC (Visual Studio), Clang
6. Platform: Cross-platform (Windows, Linux, macOS)
